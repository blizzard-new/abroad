# UniWay 辦公室工具說明（存成 uniway/工具說明.md）

這些工具就是原本辦公室每個人手上的能力：出圖、出影片、規則檢查、審核匣、發文、看留言、抓成效、自動私訊、巡查學校。
**AI 只負責想和寫，其他事都用這些工具做**，這樣規則、帳號和發文的保護和以前一模一樣。

## 怎麼呼叫

在命令列執行（`<辦公室路徑>` 是 `uniway/設定.md` 寫的那一行，通常是 `C:\你的資料夾\abroad\marketing\agent-office`）：

```
uv run --project "<辦公室路徑>" office tool <名稱> <參數>
```

- 每個工具印一份 JSON。看到 `"ok": false` 和 `error`，就是失敗了：把 error 照實告訴老闆，不要說成功。
- 檔案路徑一律寫完整路徑（例如 `C:\Users\你\OpenBot\Shared\uniway\草稿\2026-11-27_threads_1.json`）。
- 帳號金鑰由工具自己讀，你看不到也不需要；**不要**去找、不要貼、不要問。
- 工具預設是「模擬」：發文、回覆、私訊都只記錄在辦公室的 `var\outbox\`，不會真的送出。老闆自己打開「真的發」之前，你看到的 `simulating: true` 就代表是模擬。你沒有權限、也不要去打開它。

## 檔案格式

### 草稿檔（阿脆、Mori、阿剪寫）

共同欄位：`channel`、`format`、`publish_at`（發文時間，台北時間 `2026-11-27 12:30`，用 `begin-day` 給的）、`title`（一句話題目）、`source_url`（引用官方公告才填，否則 `""`）、`pillar`、`angle`（照 `begin-day` 版位的）、`payload`（內容）。

**Threads 一般貼文**（`channel: threads`、`format: text`）

```json
{"channel": "threads", "format": "text", "publish_at": "2026-11-27 12:30", "title": "預算", "source_url": "", "pillar": "value", "angle": "pain",
 "payload": {"text": "主文，不放網址", "topic_tag": "交換學生", "first_reply": "第一則留言，放 app.uniway-tw.com", "card_title": "圖上大標 8～14 字", "card_body": "圖上補充 30 字內"}}
```

**Threads 多張圖貼文**（`format: carousel`）：payload 多一個 `slides`，格式同 IG 輪播的頁面。

```json
{"channel": "threads", "format": "carousel", "publish_at": "2026-11-27 21:00", "title": "…", "source_url": "", "pillar": "value", "angle": "list",
 "payload": {"text": "主文，結尾邀請左右滑", "topic_tag": "交換學生", "first_reply": "…app.uniway-tw.com…",
   "slides": [{"kind": "cover", "title": "14 字內", "body": ""}, {"kind": "point", "title": "14 字內", "body": "40 字內"}, {"kind": "cta", "title": "收藏起來慢慢看", "body": "一句話介紹｜連結在第一則留言"}]}}
```

**Instagram 輪播**（`channel: instagram`、`format: carousel`）：6 張，第 1 張 cover，最後一張 cta。

```json
{"channel": "instagram", "format": "carousel", "publish_at": "2026-11-27 19:30", "title": "…", "source_url": "", "pillar": "value", "angle": "list",
 "payload": {"slides": [{"kind": "cover", "title": "…", "body": "…"}], "caption": "說明欄，不含 hashtag，網址寫「連結在主頁」",
   "hashtags": ["#交換學生", "#出國交換"], "art_prompt": "封面插圖描述，不含文字；有吉祥物要寫眼睛"}}
```
放進審核匣時，工具會自己多做一張限動（15 分鐘後發）。

**影片**（`instagram/reel`、`youtube/short`、`youtube/long`）

```json
{"channel": "instagram", "format": "reel", "publish_at": "2026-11-27 19:30", "youtube_short_at": "2026-11-27 18:00", "title": "…", "source_url": "",
 "payload": {"title": "…", "scenes": [{"kind": "hook", "heading": "交換預算\n你算過嗎", "lines": ["字幕一行 12 字內"], "seconds": 3, "emphasis": ["預算"]},
   {"kind": "point", "heading": "…", "lines": ["…"], "seconds": 5, "emphasis": []}, {"kind": "stat", "heading": "…", "lines": ["…"], "seconds": 5, "emphasis": []},
   {"kind": "cta", "heading": "UniWay", "lines": ["連結在主頁"], "seconds": 5, "emphasis": []}],
   "caption": "Reels 說明欄", "hashtags": ["#交換學生"], "youtube_title": "…… #Shorts", "youtube_description": "前兩行講清楚；放 app.uniway-tw.com"}}
```
- `instagram/reel`：工具會同時排一支 YouTube Shorts（時間用 `youtube_short_at`）。
- `youtube/short`：輪播改編的 Shorts，`queue` 時加 `--parent <輪播的草稿編號>`。
- `youtube/long`：每週長影片（橫式）。

### 審稿結果檔（Kiki 寫，放在 `uniway/審稿/` 同檔名）

```json
{"approved": true, "issues": [], "notes": ["口吻有點工整，可以更碎碎念"], "revisions": 0}
```
`issues` 是必須改的；有任何一條，`queue` 就會把草稿標成「需要修改」，老闆在審核匣看得到。

### 版面規劃檔（Mori 寫，選配；不給就用預設版面）

```json
{"outline": ["第 1 頁一句話", "…"],
 "spec": {"margin": 80, "title_size": 176, "body_size": 44, "line_height": 1.5, "accent": "blue", "emphasis": "chip", "page_number": "top"},
 "slides": [{"layout": "cover", "title_lines": ["交換預算", "怎麼抓"], "emphasis": ["預算"], "items": [], "labels": [], "picture": ""}],
 "art_prompt": "封面插圖描述", "issues": ["哪一頁資訊太多"]}
```
- `slides` 的頁數和順序要和文案完全一樣。第一頁 `cover`，最後一頁 `cta`，中間選 `focus`、`steps`、`compare`、`stat`。
- `title_lines` 接起來必須和原本的標題一字不差；`emphasis`、`items` 的字都要是文案裡原本就有的。
- 用法：`queue <草稿檔> --review <審稿檔> --plan <版面規劃檔>`。封面插圖若你已經畫好：加 `--art <圖檔>`；不要插圖：加 `--no-art`。

### 回覆檔（Momo 寫）

```json
{"post_id": 12, "comment_id": "17900000000", "comment_text": "住宿怎麼找？", "username": "amy", "text": "30～80 字的回覆，像真人，不推銷"}
```

### 提案檔（巡查員寫）

```json
{"author": "巡查員的名字", "verifier": "",
 "checks": [{"school": "學校名稱，照 schools 給的", "status": "new_notice", "detail": "看到什麼", "source_url": "實際看的官網網址", "suggested_update": "建議平台改哪個欄位、改成什麼，沒把握就留空"}]}
```
`status`：`no_change`、`new_notice`、`mismatch`、`unreachable`。只有 `new_notice` 和 `mismatch` 會送進審核匣，老闆核准後才會開成 GitHub 的 draft PR（合併永遠是老闆自己按）。
