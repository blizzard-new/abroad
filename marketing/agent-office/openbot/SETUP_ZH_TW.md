# 把行銷小辦公室搬進 OpenBot

OpenBot 的助理取代原本辦公室的每一位同事，而且拿到原本辦公室的全部功能：出圖、出影片、規則檢查、審核匣、發文、看留言、回覆、自動私訊、抓成效、巡查學校。

怎麼做到的：
- **助理負責想和寫**：企劃、寫稿、審稿、擬回覆、解讀數據、巡查官網。
- **工具負責做事**：`uv run office tool ...`。就是原本辦公室的程式（出圖、剪片、規則、發文的保護、各平台連線），一個功能一個指令。助理只能呼叫自己那一行的工具，帳號金鑰由工具自己讀（你以前 `office auth` 連好的，不用重連），助理看不到。
- **不再需要**：`office serve` 的時鐘、網頁、Telegram。排程由 OpenBot 的排程做，聊天由 OpenBot 的手機 app／頻道做。

> 沒辦法只靠提示詞做到這些：發文、出圖要程式。所以程式還是留在你的電腦上，只是不再自己開一個服務，由助理叫它。

---

## 1. 要建幾位助理

模型照你的決定：**Codex（gpt-6.1-sol，思考強度 high）** 和 **Antigravity（Gemini 4 Argon High）**，一律不接 Claude。模型名稱我沒辦法替你的 OpenBot 驗證，請選模型清單裡最接近的。

| # | 名字 | 工作 | 模型 | 上網 | 指令檔 |
|---|---|---|---|---|---|
| 1 | Leo 總管 | 老闆的窗口：開工、分派、轉達你的核准／退回 | Antigravity | 不用 | `agents/01-leo.md` |
| 2 | Ivy 企劃 | 讀公告和數字、上網查、排今天內容 | Antigravity | **要** | `agents/02-ivy.md` |
| 3 | 阿脆 | 寫 Threads | Codex | 不用 | `agents/03-threads.md` |
| 4 | Mori | IG 輪播文案、版面規劃、出圖 | Codex | 不用 | `agents/04-mori.md` |
| 5 | 阿剪 | 影片腳本、出影片 | Codex | 不用 | `agents/05-video.md` |
| 6 | Kiki 審稿 | 查事實、字數、連結、AI 口頭禪 | Codex | 不用 | `agents/06-kiki.md` |
| 7 | Momo | 留言回覆、自動私訊、每晚成效復盤 | Antigravity | 不用 | `agents/07-momo.md` |
| 8 | Pat 發佈 | 發文前最後檢查、發文、更新權杖 | Antigravity | 不用 | `agents/08-pat.md` |
| 9 | 巡查員（選配） | 巡各校官網，送資料更新提案 | Antigravity | **要** | `agents/09-patrol-optional.md` |

每個指令檔裡有三樣東西：要選的模型和要連的資料、貼到「指令」欄的整段文字、見面時說的第一句話。

原本辦公室的 Nana（數據）併進 Momo。原本「請新同事」的功能，在 OpenBot 就是你自己再新增一位助理。

## 2. 共用資料夾

在 OpenBot 的共用位置（`~/OpenBot/Shared`，Windows 通常是 `C:\Users\你的名字\OpenBot\Shared`）建資料夾 `uniway`，放進這些：

```
uniway\
  設定.md        ← 見下面，一行路徑
  共同規則.md    ← openbot 資料夾裡的同名檔（每位助理開工前都讀）
  工具說明.md    ← openbot 資料夾裡的同名檔（工具怎麼用、檔案格式）
  語氣.md        ← 你自己寫的口吻設定，沒有就先空白（貼 2～3 則你覺得「這就是我們」的舊貼文最有效，最多 3000 字）
  今日\  草稿\  審稿\  回覆\  巡查\    ← 助理的工作檔，空資料夾就好
```

`設定.md` 只要這兩行（把路徑換成你電腦上的）：

```
辦公室路徑：C:\你的資料夾\abroad\marketing\agent-office
工具指令：uv run --project "C:\你的資料夾\abroad\marketing\agent-office" office tool
```

每位助理要能讀寫這個資料夾，並且能在命令列執行 `uv`（你本來就用 `uv run office ...`，所以電腦上已經有）。Ivy 和巡查員要開「上網」。

## 3. 排程

OpenBot 的排程我沒看過設定畫面，所以「兩天一次」**不靠排程格式**：每天 07:30 叫 Leo 一次，由 `begin-day` 工具判斷（距上次開工滿 2 天才開工，電腦關機幾天後第一天開機也算發文日）。

| 助理 | 時間（台北） | 排程要說的話 |
|---|---|---|
| Leo | 每天 07:30 | 「依規則判斷今天是不是發文日；是就開工」 |
| Pat | 每天 10:00、12:31、18:01、19:01、19:31、21:01、23:00 | 「做發文前檢查，再發出已核准且到時間的內容」 |
| Pat | 每週一 09:00 | 「檢查帳號連線並更新權杖」 |
| Momo | 每天 13:10、20:05、21:35 | 「看發文後的留言，擬回覆」 |
| Momo | 每天 23:30 | 「做每晚成效復盤，存建議給 Ivy」 |
| Momo | 12:30～14:30、19:30～22:30 每 15 分鐘（**只有設了自動私訊規則才開**） | 「掃一輪留言關鍵字自動私訊」 |
| 巡查員（選配） | 每天 08:30 | 「巡查我的那一份學校」 |

注意：**每次排程都是叫一位 AI 助理做一次事，會用掉你的 Codex／Gemini 額度。** 舊辦公室的時鐘每 30 秒跑一次是不花額度的程式，OpenBot 不是。所以我把頻率壓到「剛好夠用」：Pat 只在發文時間前後跑，Momo 的自動私訊每 15 分鐘一次（舊的是每 2 分鐘）。額度不夠就再拉長。

## 4. 開始之前（一次就好）

1. **把舊辦公室關掉**：關掉跑 `uv run office serve` 的那個命令列視窗。它和新的助理共用同一個資料庫和帳號，兩邊同時跑會重複發文。
2. 更新程式：到你的專案資料夾執行 `git pull`。
3. 檢查帳號還連著：

```bash
uv run office tool accounts --ping
```

   Threads、Instagram、YouTube 顯示連上就好；沒連上的才用 `uv run office auth threads`（或 `instagram`、`youtube`）補連。

4. `.env` 裡原本的設定照舊（`OFFICE_DRY_RUN=0` 等）。工具自己多一道鎖，見第 6 節。

## 5. 建助理和試跑（先模擬）

1. 建好 `uniway` 資料夾（第 2 節）。
2. 依序建 8 位助理（先不建巡查員）：選模型、貼指令欄、開資料夾權限（Ivy 開上網）。
3. 每位建好後，貼他的「第一句話」。檢查他有沒有讀到 `共同規則.md`、說的「交給誰」對不對；不對就糾正。
4. 跟 Leo 說「開工」。**這時工具還在模擬模式**：圖和影片真的會做，審核匣真的會有，但發文只會記錄在 `abroad\marketing\agent-office\var\outbox\`，不會送出。
5. 看結果：
   - Leo 傳來今天的清單；
   - 審核匣：`uv run office tool list`（或 `uv run office serve --no-clock` 開網頁／手機 app 看，加 `--no-clock` 就不會再自己跑時鐘）；
   - 草稿品質不滿意，就把意見寫進 `語氣.md`。
6. 回 Leo「核准 1」，再叫 Pat 發文，看 `var\outbox\` 有沒有記錄。

## 6. 正式啟用

全部試順了，在你的電腦執行這一行（只有你能做，助理沒有這個工具）：

```bash
uv run office tool live on
```

它會告訴你現在是模擬還是正式。要真的發文需要兩件事同時成立：這個開關是 on，而且 `.env` 的 `OFFICE_DRY_RUN` 是 0。想暫停就執行 `uv run office tool live off`，立刻回到模擬。

**第一則真的發文，建議你自己在旁邊看：** 核准一則 Threads，叫 Pat 發，確認貼文真的出現在你的帳號、第一則留言（放連結的）也在。

## 7. 和原本辦公室不一樣的地方

- **Threads 的單張配圖**用預設版面（以前 Mori 會為每張圖重新規劃）。IG 輪播和 Threads 多張圖仍然是 Mori 規劃的版面。
- **排程由助理觸發**：電腦要開著、OpenBot 要開著；電腦關機的時段，排程不會補跑（兩天一次的規則會讓第一天開機自動算發文日）。
- **留言自動私訊**頻率從約每 2 分鐘降到每 15 分鐘，新留言的人會晚一點收到。
- **雙保險仍在**：回覆陌生人的留言永遠等你核准；資料更新提案永遠等你核准，核准後也只開 draft PR；發文失敗不會自動重發，第一則留言失敗時貼文不會被當成失敗。
- **沒有搬過來的**：舊辦公室的網頁動畫辦公室、手機 App 的對話（Leo 改成在 OpenBot 對話）、舊的 Telegram 橋接。審核匣的網頁／手機 App 仍可用（`uv run office serve --no-clock`）。
- **我沒辦法在 OpenBot 裡實測的地方**：助理能不能順利在你的電腦執行指令、排程怎麼設、模型名稱。第 5 節的試跑就是在確認這些；卡住就把 Leo 或該助理回的錯誤訊息貼給我。

## 8. 出問題怎麼辦

| 狀況 | 怎麼辦 |
|---|---|
| 助理說「執行不了指令」 | 確認他有「執行指令」的權限，`設定.md` 的路徑對、電腦上 `uv` 能用（命令列打 `uv --version`） |
| 工具回 `"ok": false` | 助理會照實轉述 error；多數是草稿檔格式不對，`工具說明.md` 有格式 |
| 草稿一直標「需要修改」 | 審核匣裡看問題清單，不放心就退回、請作者重寫 |
| 想知道現在是什麼狀態 | `uv run office tool status` |
| 要全部停下來 | `uv run office tool live off`，再把 OpenBot 的排程關掉 |
| 想回到舊辦公室 | 關掉 OpenBot 的排程，開 `uv run office serve`（資料和帳號都沒動，直接接續） |
