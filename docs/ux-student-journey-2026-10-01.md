# UniWay：交換學生的操作流程與 UX 優化方案

日期：2026-10-01。狀態：操作檢視與實作提案，尚未實作本文件的改動。

本輪實際檢視 Web 的我的申請、選校規劃、日曆與申請文件，並讀取現有選校與時程處理程式。只瀏覽既有帳號狀態，沒有提交新條件、改選目標、建立任務或填寫私人文件。這是設計檢視，不是真實學生訪談或首次使用者測試。

## 學生想完成的事

「我想知道自己能去哪裡、負擔得起嗎、現在來得及嗎，以及今天該做什麼。」

產品的主要操作應是：填一次條件 → 比較候選 → 確認志願 → 預覽準備計畫 → 按階段完成申請。學生不應先學會各個工具的差異，才能開始準備。

## 建議的完整操作

| 階段 | 學生操作 | 系統接手的工作 | 接著看到的主要動作 |
| --- | --- | --- | --- |
| 探索 | 看貼文、搜尋學校；準備申請時點「開始我的交換計畫」 | 保留搜尋與瀏覽位置，介紹需要哪些基本條件 | 開始配對或繼續上次進度 |
| 填條件 | 選母校、系所、學制、預計出國學期、學業與語言狀態、預算與偏好 | 系所連動；允許尚未考語言／尚未決定；區分必填與可稍後補；已有資料預填 | 查看適合我的學校 |
| 看候選 | 比較少量候選，展開完整清單；收藏仍只表示有興趣 | 分開已知符合、仍待確認、已知不符；說明學院、語言、當期開放、費用與課程限制 | 比較候選／確認志願 |
| 定志願 | 排列志願與備選，確認申請年度及梯次 | 校內甄選是共用流程，合作校申請各自成分支；顯示未確認的資格，不把收藏自動當申請 | 預覽我的準備計畫 |
| 排時程 | 看過建議任務與日期後加入日曆，可調整可投入時間及準備天數 | 依有效官方期限倒推；各任務分別估計工作量；考慮先後依賴、共用文件與多校衝突 | 開始下一項任務 |
| 準備文件 | 打開任務、使用正確當期表格、填寫並核對附件／簽章 | 可沿用的基本資料只填一次；保留草稿；顯示當前階段必備、條件式與準備工具的區別 | 繼續填寫／檢查這份文件 |
| 準備送件 | 核對送件方式、寄出或送達期限、附件、份數、收件單位 | 整理核對清單與所選列印包，提供官方送件入口 | 前往官方送件／記錄已送件 |
| 回訪 | 查看今天的任務、等待項目與官方規定變更 | 接續原進度；條件或目標變更時先預覽影響；保留仍適用的完成項目 | 繼續準備，而非重新建立計畫 |

首頁維持使用者已指定的社群貼文定位。申請者可以從既有「我的申請」入口接續準備，必要時提供小型繼續入口；不重新放回已刪除的大型探索橫幅與目的地展示。

## 減少功能重複的方法

- **選校規劃、詳細資格核對**：共用一份條件資料與一個候選決策流程；詳細規定保留為候選卡中的可展開核對，不要求先跑第二套流程。
- **收藏、比較、志願**：沿用同一候選清單，但保留「有興趣／正在比較／正式志願」不同意圖；不把收藏操作當成建立申請。
- **日曆、官方期限、準備安排**：同一時程工作區的三種內容，區分不可任意變更的官方截止與可調整的個人工作安排。
- **文件填寫、檢查、文件庫、列印包**：整合為一份文件的處理進度；完成填寫後直接接核對與下載，不要求回側邊欄找另一個工具。
- **預算、補助**：選校比較先顯示費用完整度與預估範圍，再展開明細；來源不足時不聲稱符合預算，也不把未確定補助算成必得收入。
- **申請指南**：保留公開知識用途，並從每個任務連到相關說明；不要求學生先讀完整指南才可開始配對。

## 我的申請頁應該回答的三件事

1. 我目前在什麼階段，為哪個年度與哪些志願準備？
2. 下一個可執行的動作是什麼，完成它需要什麼資料？
3. 有什麼正在阻擋我：未確認資格、缺官方文件、期限太近，或正在等校方回覆？

突出一個主要動作，旁邊放本週少量任務、即將到期項目與等待項目。推薦、完整日曆與工具入口放在需要時的位置，不把所有模組都擺成同等重要。

## 自動規劃的邊界與回復操作

- 自動帶入既有條件、整理候選與共用待辦；顯示配對理由與資料缺口。符合度不是錄取機率。
- 已有排程僅使用有效、適用年度／梯次相符、有來源且未過期的官方期限，保留這個限制。未知日期可建立無日期的「確認期限」任務，不能編出截止日。
- 將官方規定與個人準備估計分開；來源不足不代表學生本身不符合資格。
- 換校或改條件前顯示受影響任務、文件與資格，確認後才套用；保留可重用資料，避免靜默清除進度。
- 表單離開後保留草稿，失敗時就地重試，回學校搜尋保留條件與位置；重複建立同一計畫不得重複新增共用任務。
- 「文件已填」「已核對」「已送出」「校方受理」「已錄取」是不同狀態。系統不代替學生正式送件，也不因按下勾選就宣稱校方已核准。
- 機器輔助用於整理與解釋；資格、正式要求與期限綁定官方資料。沒有啟用模型時不宣稱正在使用 AI 模型。
- 沿用圖示側邊欄風格，提供鍵盤焦點時的中文字提示、觸控入口與目前位置；不讓操作只依賴滑鼠移入。

## 後續 Web 實作順序

1. **主線與共用狀態**：統一條件、年度、學期與志願；修正推薦資格分組；我的申請顯示下一步與具體阻擋原因。
2. **選校接時程**：日曆空狀態串接既有時程預覽；取得不到日期時能繼續核對；再加入逐任務天數與依賴。
3. **時程接文件**：依階段組織文件，從待辦直達指定文件，列印包只顯示選中內容。
4. **狀態與回復**：切換目標預覽影響、草稿保留、重試去重、變更提醒與送件狀態。

先完成 Web 的完整學生操作，再依使用者核准的範圍處理 App。本文件未新增 UI 元件、改寫申請規則或啟用 AI。

## 驗收情境

- 初次使用者可以先看學校；個人規劃時只填一次同義資料，沒有語言成績也能看清楚缺口。
- 學生能解釋候選為什麼適合、哪項資格仍待確認，並分辨合作備查與當期可申請。
- 選定目標後可在同一主線預覽時程；沒有有效官方日期時看到明確核對動作，而不是空頁或虛構日期。
- 文件任務能直接帶到對應表格；未來階段文件不干擾當前準備；官方表格與準備草稿清楚區別。
- 中途離開、重新整理、返回搜尋或重試，都能恢復狀態；不重複新增任務或清除適用的完成資料。
- 多志願共用校內甄選任務，各校提名後步驟分開；換校時預覽差異。
- 桌面、手機與鍵盤操作皆能找到同一個下一步。另請未使用過系統的學生實際完成「找候選→確認志願→找到下一項任務」，再用觀察到的卡點修正。
