## 1. 隱私與證據規則

- 受測者只使用隨機代碼，例如 `STUDENT-001`；不要記錄姓名、Email、學號、學生證影像、OAuth subject、session token 或裝置識別碼。
- 不把真實申請文件、成績、證號、電話、住址或未遮蔽截圖放進 repository。需要畫面證據時，先以測試資料重現並確認沒有私人 sidebar、瀏覽器 autofill、通知或其他帳號資訊。
- 學校與學系只記錄重現問題所需的最低範圍；小樣本可能重新識別個人時，改記錄「長庚／臺北大學＋學院類別」或只記權限身分。
- 官方規定問題必須附精確官方來源 URL、頁面標題、適用年度／梯次與人工查核日期；社群、搜尋結果或 AI 回答不能當官方證據。
- findings 只能記錄觀察與處置，不得直接修改正式 workflow、補查核日期、形成雙審、發布資料或宣告 Web 核准。

## 3. Web 走查情境

這一階段只驗 Web；`WEB-09` 的 Flutter 對等刻意不在本模板內，必須等 C-03 明確核准後才進入 D 階段。

| 情境 ID | 真人任務 | 完成證據 | 必查負面邊界 |
| --- | --- | --- | --- |
| WEB-01 | 未登入搜尋、篩選並比較至少兩所合作校 | 能指出支援狀態、年度、來源與「合作備查／可申請」差異 | 未登入比較不寫入收藏或個人計畫 |
| WEB-02 | 登入、完成 Email 與學生身分流程 | 能辨認一般帳號與已驗證校籍權限差異 | 不輸入校務密碼；學生證未同意時 0 上傳 |
| WEB-03 | 選擇本校、學系、年度、梯次與志願 | 個人申請計畫只出現適用規則與待確認警示 | 不把缺值、參考年度或合作名單推測成可申請 |
| WEB-04 | 取得個人申請清單與官方表格 | 能開啟官方來源並辨識份數、正影本、簽名與核章 | 未發布或來源不足的表格不冒充正式版本 |
| WEB-05 | 填寫一般欄位、預覽並核對文件 | 缺值保持空白；修改後舊核對失效 | 登入不等於同意上傳敏感檔 |
| WEB-06 | 下載 PDF，依指示準備列印與附件順序 | 能說明實際份數、附件順序及簽核位置 | 損壞附件不得被靜默略過 |
| WEB-07 | 記錄紙本、線上或混合送件進度 | 能區分寄出、必須送達、學生自記與平台未代送 | 參考時程不建立精確提醒 |
| WEB-08 | 查看提醒、外部日曆與規定更新 | 能關閉提醒並理解來源與適用範圍 | Email 預設關閉；降級方案的 feed 不再更新 |
| WEB-10 | 在公共板與對應大學交換板閱讀、發文與留言 | 能預覽匿名／本名／已驗證校系的公開身分 | 訪客只讀；一般驗證帳號不可跨校發言 |
| WEB-11 | 管理私人資料、文件同意與刪除帳號 | 能下載／永久刪除文件並理解公開內容去識別 | 私人資料不出現在其他帳號、社群或快取 |
| WEB-12 | 以已驗證學生回報目前可見申請規定錯誤，再由內容管理員於獨立佇列結案 | 能辨識公開 HTTPS 官方來源、結果不明同 mutation ID 重試，以及「成立不等於正式規定已修改」 | 訪客／未驗證／跨母校拒絕；私人聯絡資料拒絕；404／409 重新載入；結案不得建立 revision、approval 或 publication；匯出、刪帳去識別與 retention 符合政策 |

每個情境都要以桌面版與 390px 手機寬度各走一次；鍵盤焦點、錯誤訊息、螢幕閱讀器狀態與水平溢位也屬可記錄 finding。

## 4. Finding 分級與狀態

| 等級 | 定義 | Web 核准規則 |
| --- | --- | --- |
| P0 | 可能讓學生錯過資格／期限、寄錯單位、漏交必要文件，或造成個資未經同意保存 | 一律阻擋；修正、回歸與真人重驗前不得關閉 |
| P1 | 關鍵規定沒有官方來源、年度、梯次或雙人查核；不同資料面互相矛盾 | 一律阻擋；不能以風險接受代替修正 |
| P2 | 主要任務可完成，但名稱、提示、RWD 或可及性造成明顯困惑 | 必須修正，或由產品負責人留下具體接受理由與後續任務 |
| P3 | 不影響正確性與完成任務的外觀或文字改善 | 可排程，但仍需明確處置決定 |

允許狀態只有：`open`、`triaged`、`fixing`、`ready_for_retest`、`closed`、`accepted_p2_p3`。P0／P1 不得使用 `accepted_p2_p3`。只有重現步驟已失敗、修正證據存在、對應 regression test 通過且原受影響情境真人重驗通過時，才能改為 `closed`。

## 5. Finding 記錄模板

每個問題複製一份下列區塊；ID 依序使用 `FINDING-001`、`FINDING-002`。不要刪除空欄，也不要用「同上」取代可重現資訊。

### FINDING-NNN

- 狀態：`open`
- 嚴重度：`P0 | P1 | P2 | P3`
- 發現日期：`YYYY-MM-DD`
- 發現角色：`產品負責人 | 測試學生 | 資料審查者`
- 工作階段代碼：`SESSION-YYYYMMDD-NNN`
- 對應情境：`WEB-NN`
- 母校／權限身分：`不得填帳號或真實姓名`
- 路由／功能：`/route 或功能名稱`
- 瀏覽器／視窗：`瀏覽器版本；寬 × 高；縮放比例`
- 審核包：`candidate；總指紋；流程子指紋；生活情報子指紋`
- 負責任務：`B1-01～C-03 中的一個或多個任務 ID`

重現步驟：

1. 待填。
2. 待填。
3. 待填。

預期結果：待填。

實際結果：待填。

學生影響：待填；說明是否會外搜、誤解下一步、漏文件、錯期限、錯送件方式或洩漏私人資料。

官方來源／產品證據：待填；官方規定問題須附 URL、標題、年度／梯次及查核日期，介面問題附不含個資的測試資料重現路徑。

處置決定：`修正 | 要求資料真人查核 | 拒絕為非問題 | accepted_p2_p3`；附理由與決定者角色，不填姓名。

修正檔案／版本：待填；列出檔案、revision／commit（若有）及是否影響 API contract 或正式資料。

自動回歸：待填；列出新增或更新的測試與實際結果。

真人重驗：待填；列出工作階段代碼、日期、同一情境與結果。

關閉條件檢查：

- [ ] 原重現步驟在未修正版可重現。
- [ ] 修正後原步驟不再重現。
- [ ] 受影響及相鄰自動測試通過。
- [ ] 真人以相同審核包或明確記錄的新審核包重驗。
- [ ] 若為官方規定，兩位資料審查者證據與正式發布流程皆完成。
- [ ] 未把測試、模板或單一管理者操作誤記成雙審／核准。
