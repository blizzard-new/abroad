# UniWay Web：學生申請主線 UX 改動

日期：2026-10-02。依據 `ux-student-journey-2026-10-01.md` 的實際操作卡點改善。首頁仍以討論貼文為主，Web 保留既有玻璃風格與圖示側邊欄。本輪未修改 App、部署或執行正式送件。

## 已實作的操作

| 原本的卡點 | 現在的操作 |
| --- | --- |
| 工具很多，不知道先做哪件事 | 「我的申請」突出一個下一步：填條件、選校、核對資格、安排時程或準備文件；已保存目標尚無資格比對時先引導核對 |
| 推薦排序與資格訊息衝突 | 以已知基本條件相符、資格待確認、目前條件不符分組，同類再依排序分數排列；不符組預設收合且不提供直接選為目標；待確認組明確標示暫定意圖 |
| 缺資料被誤讀為不符或已通過 | 空白、條件式範圍、錯放學制的學院欄皆為待確認；成績門檻缺漏不再使用預設 70 分宣稱通過；英文 undergraduate 不會誤判為 graduate |
| 出國學期在別處要重填 | 出國學期在主要條件區；春季／秋季帶入第二／第一學期；不從出國年份推定申請學年度；學院、系所、學制、年級可帶入尚未填寫的文件共用欄位 |
| 尚未考語言就難以開始 | 可提交部分已知條件，未知學業／語言分數保存為空值；可以探索學校，同時保留缺口說明 |
| 日曆空狀態只有手動新增 | 直接前往目標學校時程預覽，焦點放在學年度；手動任務是次要入口，點擊後直接開啟表單 |
| 沒有官方日期時卡住 | 顯示核對事項、官方來源、期限來源入口、手動任務和可複製的詢問草稿；不產生虛構官方日期 |
| 所有任務一律用相同準備天數 | 預覽中可逐項設定 1–90 天；修改後重新計算並核對日期才可加入；已有任務保留原本天數與進度，重複加入去重 |
| 文件與列印包都展開整個工具庫 | 目前階段展開，其他階段收合；可切換查看階段，但不因此變更送件／錄取狀態；文件卡勾選加入，列印包只顯示所選項目 |
| 官方文件缺漏沒有具體下一步 | 明示適用年度、梯次、文件、附件、份數、簽章與送件單位要確認；提供官方文件入口、詢問草稿、讀取失敗重試 |
| 換校可能讓準備進度失去脈絡 | 推薦卡或文件設定更換既有目標前，顯示影響並可取消；保留原校任務與草稿，重新核對適用規定；Esc 不會沿用上次確認結果 |
| 文件完成、下載與送件混淆 | 填寫頁連到文件檢查／官方規定；明示草稿完成、逐欄核對、PDF 匯出與正式送件／校方受理／錄取不同 |
| 更新或非同步回應可能干擾填寫 | 同帳號／母校的選校表單正在修改時保留輸入；顯示尚未更新方案；切換帳號／母校的舊回應不套用到新條件 |

## 仍保留的資料與產品邊界

- 「已知基本條件相符」只指目前可讀取的學院、學制與成績門檻，仍須核對科系、課程、年度、梯次及當期公告；排序分數不是錄取機率，也不是預算已經足夠。
- 推薦是有限候選集，顯示各組少量卡片；完整合作校仍從學校搜尋查看。已保存目標另行比對，即使它不在前 20 個候選中。
- 日期預覽仍要求流程已發布、適用狀態確認、年度／梯次相符、截止日來源有效且未過期。準備天數由學生設定，使用日曆天。
- 官方表格與準備草稿保持區別；既有列印權限與目前內容核對仍有效。切換文件查看階段不代表學生通過校內初審。
- 多校任務保留各自學校，既有日曆仍能做衝突分析。本輪未建立新的共用校內甄選任務模型，亦未把流程排列順序推定為可自動排程的任務依賴。
- 未新增費用推估資料、未啟用付費 AI 模型、未對外詢問或正式送件。官方資料缺漏仍需來源補充與查核。

## 驗證方式

針對性 Python 測試、隔離測試帳號的瀏覽器流程，以及本機現有頁面的唯讀檢視。隔離流程涵蓋 390px 與 1754px、資格分組與資料異常、目標變更取消／保留、逐項準備天數、過期／不適用／無來源日期、日曆空狀態、文件階段切換、列印去重與核對後 PDF 下載。真實帳號未重新提交條件、換校、建立任務或填寫私人文件。

結果：42 項針對性測試通過（184.68 秒），涵蓋 tests/test_advisor.py、tests/test_calendar_task_scheduling.py、tests/e2e/test_planning_workspace.py、tests/e2e/test_student_journey_ux.py、tests/e2e/test_application_ui_refinements.py。app.js 通過 node --check；本輪修改的既有檔案通過 git diff --check。這不是全專案測試或正式部署驗收。
