## 證據標準

- `verified_current`：已讀官方原文；值、年度、梯次、身分、校區和適用計畫吻合，附 URL、查核時間與原文定位。
- `verified_reference`：官方支持該內容，但只適用原文明示的歷史期間或一般參考範圍。
- `contradicted`：原文與顯示值不符，或來源實際不支持該項主張。
- `missing`：必要欄位沒有可用內容。
- `needs_confirmation`：已有內容，但適用性、來源或證據不足。
- `source_unavailable`：本輪未取得原文，記錄實際失敗；不推論官方未公告。
- `not_applicable`：有具體理由說明該欄位不適用；不得用來掩蓋未查。
- `pending_review`：尚待逐項比對。新增盤點不會自動改成已驗證。

同一官方條文可以支持多筆紀錄，但必須列明對應紀錄，逐筆確認適用範圍。HTTP 200、字串相符及檔案雜湊相同只作輔助證據。來源更動、資料更動或版本不同時，不沿用失效結論。

## 執行順序與完成條件

1. 盤點全部母校、合作方案、公開欄位及產生內容的程式，保留可重跑清單。
2. 擷取並記錄每個來源的實際讀取結果；優先處理期限、名額、資格、金額和文件。
3. 逐筆做語意與適用範圍比對；缺資料的項目補查正確的官方來源。
4. 更正有證據的錯誤；仍無法確認的內容保留具體缺口和後續所需證據。
5. 產出 25 校總表與逐合作校／逐欄位結果，核對總數及未完成數。
6. 執行與修改相符的測試，建立 PR，清楚列出已核實與仍缺證據的部分。

完成盤點或建立 PR 都不代表本委託完成。必須確認清單中的每筆資料都已處理，沒有遺漏的公開資料來源或未檢查的衍生內容。

## 已確認的查核風險

1. `school_completeness.py` 部分 available 判斷只看欄位是否存在或是否含缺漏字詞，不能解讀為官方事實已驗證。
2. `cross_school_partners.py` 的國家生活費預設值會產生逐校摘要；其 source URL 可繼承母校交換頁或其他主題的國別指南連結。需要逐項確認金額證據，不能以附有 URL 作為來源充分的判定。
3. `data/processed/` 雖只有佔位檔，網站另使用 `official_data/` 內建資料、各校 adapter、程式常數及編輯補充，均需納入。

以上是程式與資料來源關係的確認，尚不是全部學校內容的查核結果。
