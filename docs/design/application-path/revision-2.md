# Phase 1 V2：一關一件事，向上出發

日期：2026-10-29。網站設計預覽，尚待使用者確認；不是正式功能上線。

## 為什麼上一版每關像同一頁

V1 的節點與說明卡不同，但文件動作仍連到共用的 `/#application-center` 入口。它只完成導覽提案，沒有把舊工作台拆成對應任務。V2 不再把這個入口當作各關的主要動作；每關使用獨立 `#level/<id>` 畫面及狀態。

## 結構與範圍

「我的申請」正式改版方向是：**申請地圖 + 進度總覽 + 單關辦理**，取代原三階段工具集合的主要入口。正式版仍保留舊深連結與既有工具能力；不是在舊入口上再疊一份地圖。此次只改獨立預覽，尚未更動正式路由。

| 階段 | 小關數 | 一次處理的事情 |
|---|---:|---|
| 找到你的方向 | 3 | 母校、出國學期、交換目標 |
| 釐清申請條件 | 3 | 資格、語組、時程 |
| 寫出交換的理由 | 3 | 動機、選校原因、研修目標 |
| 規劃交換的收穫 | 3 | 一門課、預期成果、返國學習 |
| 整理研修計畫 | 2 | 組合預覽、格式與語言 |
| 備齊成績與語言證明 | 3 | 成績單、排名、語言證明 |
| 整理申請表 | 2 | 表格資料、簽名版本 |
| 完成校內送件 | 3 | 志願順序、文件檢查、自行記錄送件 |
| 追蹤校方通知 | 2 | 審查與提名通知紀錄 |
| 完成交換校申請 | 3 | 當期清單、文件、自行記錄送件 |
| 把出發準備好 | 4 | 簽證、住宿、保險、選課 |
| 完成交換的最後一哩 | 3 | 抵達回報、心得、學分採認 |

以上 34 關依既有範例拆分。六段寫作及課程筆記是準備輔助，不是新增校方必填要求。正式適用性、必填性及數量必須由原有規則與文件目錄決定，不能將預覽目錄直接套用到所有大學。

## 地圖與進度

- 第 1 關在底部，依序往上；每個相鄰節點交替左右，跨章節保持連線。節點 70px，目前關卡 76px。
- 章節 DOM 保持 1→12，視覺由下向上；鍵盤與輔助科技維持順序。
- 進入地圖定位目前關卡；工具列提供起點、目前關卡及階段跳轉。
- 每關有進度條；另有階段、整體與進度總覽。粒子僅在當前／主要進度更新後短暫播放，以 transform / opacity 為主，減少動態模式停用。
- 本地範例共 32 個個人關卡、62 個小步驟。文字／文件通常是「留下內容 + 個人確認」；核對關依項目計數，選擇關確認後計一步。百分比依實際資料相加。
- 兩個外部通知節點只表示紀錄有無，**不加入個人準備分母**。送件也只有個人紀錄，不變成校方已受理。
- 組合文章前需要六段內容；送件檢查前需要相關文件。這兩種是工具本身的依賴，可先打開查看缺項。其餘可提前處理。

## 資訊減量

1. 每關首先顯示一個問題及一個主要動作。
2. 必要的限制留在動作附近，例如官方時程缺資料、送件需自行操作。
3. 寫作提示按需展開；完整原文摘要與來源放在折疊區。
4. 圖二的課程大面板拆為一門課的筆記與官方資訊連結；圖四的六段工作台拆為六小關，最後自動集中。
5. 圖三的冷啟動、30 份解鎖等內部產品策略文字不放入新的申請主流程；既有社群功能並未在正式程式中刪除。
6. 不依相互衝突的舊字數／頁數標示宣稱確切上限，改提示核對當期格式。沒有新查核資料。

## 預覽與正式版的差距

**已能試：** 獨立關卡、局部暫存、重整恢復、示意計畫隔離、進度計算、完成回饋、章節成就、總覽篩選、草稿組合及文字下載、保存失敗重試。

**仍未接入：** 正式帳號同步、真實文件上傳／檢查、正式 PDF/DOCX、方案權限及所有母校動態流程。文件關只保存示意檔名，文字只存本機，不把模擬當作正式服務。

正式整合延續 [Phase 0 最小後端方案](phase-0-and-design.md)：

- 以不可變 plan_id 隔離帳號、母校、交換校、年度、申請梯次及出國學期。
- 在 plan-scoped draft 中保存段落與欄位；小關引用穩定 task_id、step_id、draft_id 或 vault file_id，不能只存一個完成勾選。
- 個人 confirmed 狀態與官方 submission/notification 紀錄分開；完成前依服務端適用清單驗證。摘要關卡不重複計算同一份文件的完成。
- 使用既有認證、owner 檢查及 revision 衝突流程。切帳號／計畫使過期請求失效，不將前一份文件寫到下一份計畫。
- 舊文件不猜學期、不靜默合併；保留原資料，提供明確的複製入口。
- 正式檔案仍使用既有私人 vault、寫作與匯出服務，單關 adapter 只展示對應欄位與必要提醒。

沒有修改正式前後端、資料庫、學校資料、原生 App 或自架 Docker 部署。沒有套用 migration、部署、建立或合併 PR。依使用者原定流程，須先確認修訂後外觀，才進入 Phase 2。
