## 1. 計畫目標與邊界

本計畫把規格拆成可獨立開發、測試及驗收的小任務。下一階段的交付終點是：長庚大學與國立臺北大學學生能在 Web 與 Flutter 完成相同的探索、資格確認、個人申請計畫、文件準備、送件進度、提醒及社群流程，且兩端共用帳號與資料。

本階段不包含：直接向學校正式送件、接收審查或錄取結果、校方後台、長庚與臺北大學以外的完整申請流程、完整語言學校／海外學位流程、原生 SwiftUI／Kotlin 新功能、封測期間正式扣款。

## 3. 共通測試層級

後續任務所稱測試，依風險使用以下層級：

1. Python 單元／API 整合：`python -m pytest <指定測試檔> -q`。
2. 完整後端回歸：`python -m pytest -q`。
3. JavaScript 靜態檢查：`node --check src/exchange_info/static/app.js`。
4. Web 瀏覽器端到端：以 Playwright 驗證桌面及 390px 手機版、鍵盤操作、網路請求與 console。
5. Supabase：在本機／測試專案依序套用全部 migration；特別驗證 `20260821190000_transient_auth_state.sql`、四份 2026-08-23／24 原子 migration、`20260829100000_atomic_account_deletion.sql` 與 `20260830100000_application_workflow_issue_reports.sql` 的 RLS、service-role-only RPC、固定鎖序、同身分並行、provider 唯一性、exact-session／workspace revision／submission-progress／停權與 moderation expected CAS、錯誤回報 submit／review CAS、冪等、每小時限流、資料庫時鐘、同交易日曆投影／audit、公開／私人社群內容、parent validation、刪帳去識別、90 天 retention／24 小時 terminal replay grace／purge、刪帳後不復活、Storage durable cleanup，以及 direct DML 撤銷。
6. Flutter：`flutter analyze`、`flutter test`，並在 iOS／Android 模擬器執行相同使用者情境。
7. 資料正確性：每一條關鍵規定回查官方來源、適用年度、梯次、最後查核日期，不能只測 JSON 格式。

#### B4-LAI：Ollama＋Gemma 4 12B Web 本機原型（LAI-00～LAI-03 已完成；產品串接未核准）

##### 目標、假設與硬邊界

- 原型只在目前 Windows 開發電腦執行；已盤點硬體為 RTX 5060 Ti 16 GB VRAM、約 64 GB RAM。第一階段只保證單機、單一推論佇列，不宣稱可支援公開網站流量。
- Web 瀏覽器與未來 App 都不得直接連接 Ollama。所有輸入必須先進既有 FastAPI，經登入／權益／同意、已查核來源檢索、輸出驗證及引用組裝後才可交付。
- Ollama 只允許 `http://127.0.0.1:11434` 或等價 loopback 位址；不得接受任意 URL、LAN 公開綁定、cloud model 或第三方 fallback。模型下載是獨立且可見的人工動作，不能由 Web request 觸發。
- `gemma4:12b` 只負責解釋、摘要、比較、改寫與翻譯。資格、期限、文件、送件方式、條件符合度及提醒日期仍只由已審核的結構化官方規則計算；模型輸出不得回寫或發布為正式規則。
- Advisor 第一個可驗收切面只讀取 server 選出的官方來源摘錄；引用由 server 依 retrieval 結果建立，不能信任模型自行產生的網址或來源名稱。
- 個人文件、表單內容與 AI 對話不建立新資料庫、不永久保存、不用於訓練，也不寫入 log。登入、文件庫同意或訂閱權益都不能代替每次 AI 傳送前的明確同意。
- 正式環境繼續 fail closed，AI runtime 保持 `paused`。本機原型通過全部測試與人工走查後，仍須另行核准才可決定是否擴大範圍。

##### 預定資料流

```text
Web 表單
  -> FastAPI 登入／權益／fresh consent
  -> 結構化規則 + 已查核官方來源檢索
  -> prompt 最小化與去識別
  -> LocalGemmaProvider
  -> Ollama loopback: gemma4:12b
  -> JSON Schema 驗證 + 規則衝突檢查
  -> server 組裝官方引用
  -> private, no-store Web response

任何一步失敗
  -> 不重送敏感內容、不切換 cloud model
  -> Advisor 回到現有 source-grounded／規則式結果
  -> 純 AI 功能顯示可重試的本機服務離線訊息
```

##### 原型完成條件

只有同時符合以下條件，B4-LAI 才能標記為「Web 本機原型完成」：

1. `gemma4:12b` 與 `embeddinggemma` 的來源、版本、digest、授權及人工安裝方式可重現，且推論只走 loopback。
2. 固定規則、資格、期限、文件與送件結果在 AI 開啟前後完全相同；模型不能覆蓋 server 計算值或官方引用。
3. Advisor 在模型離線、逾時、busy、輸出無效或來源不足時仍可安全降級；搜尋、比較、個人清單與表單不受影響。
4. 文件功能具 fresh consent、最小化、去識別、`no-store` 與 0 內容 log 證據；模型輸入、輸出與原檔沒有新增持久化位置。
5. OpenAPI、unit、integration、真實 Ollama 與 1440px／390px Chromium 測試全部通過，且固定效能門檻無 OOM。
6. `docs/local-ai-web-review.md` 完成人工來源核對並列出錯誤案例；產品負責人另行明確核准前，production 仍為 `paused`，Flutter、SwiftUI 與 Kotlin 維持不修改。

##### 建議實作批次與不可跳過的閘門

1. **批次 LAI-A：runtime 基線。** LAI-00～LAI-02；先證明未啟用時 fail closed，再由操作者明確安裝與下載。
2. **批次 LAI-B：provider 與來源問答。** LAI-03～LAI-05、LAI-07；先完成 mock／隔離測試，再執行真實 Ollama 測試。
3. **批次 LAI-C：敏感資料與 Web 體驗。** LAI-06、LAI-08；Advisor 經人工確認後才能讓任何個人文件進入本機模型。
4. **批次 LAI-D：可靠性、安全與審核。** LAI-09～LAI-11；未達門檻就維持原規則式產品，不得以換模型、開 cloud fallback 或降低隱私測試來通過。
